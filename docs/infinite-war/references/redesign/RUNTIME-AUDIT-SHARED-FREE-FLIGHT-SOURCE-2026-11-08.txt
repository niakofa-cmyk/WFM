. Runtime audit: the starting point
I found an important distinction in the repository:
- main is still at 3ecff671.
- The API server already has a WebSocket infrastructure running at 30 simulation ticks per second.
- Existing multiplayer ships are simulated on the server and broadcast through snapshots.
- However, the socket server is currently built around temporary match rooms, not persistent shared free-flight sessions.
- The existing authenticated HTTP middleware does not automatically authenticate the separate WebSocket upgrade.
- The existing six-location world model is not an infinite spatial simulation.
This gives us a useful foundation: we can extend the existing authoritative multiplayer infrastructure rather than invent a second networking system.

I would not expose the current match-room player snapshots as public universe presence. They have different security, identity, persistence and lifecycle requirements.

C. Authentication and spatial privacy
Integrated the new runtime into the existing authenticated socket server.

The server now:
- Verifies the player's existing Clerk session.
- Retrieves faction, selected ship and current location from the database.
- Determines spatial-session membership itself.
- Rejects client-selected spatial sessions.
- Prevents clients from submitting authoritative coordinates.
- Sends nearby positions only to authenticated participants in the same session.
- Keeps account IDs and player names out of actor snapshots.
Public presence remains anonymous.
D. Reconnection and validation
I also added:
- Monotonic input sequencing.
- Input rate limiting.
- Invalid-packet rejection.
- Reconnection using the existing server-owned actor.
- Sequence continuation after reconnect.
- A 15-second disconnect grace period.
- Bounded session and actor capacity.
One particularly important correction: a delayed socket-close event cannot detach a pilot's replacement connection.

2. Socket integration
Modified the existing socket server rather than introducing a competing networking service.
Updated socket serverThe new connection mode is:

/ws?freeflight=1

It uses the existing authentication infrastructure.

The feature is deliberately disabled by default. Enabling it requires:

ORBITAL_FREE_FLIGHT_ENABLED=true

and a configured database connection.

No production deployment or database migration was performed.
