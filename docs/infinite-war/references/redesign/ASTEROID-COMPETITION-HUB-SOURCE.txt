Imagine approaching an asteroid in the WFM universe.

The asteroid is an active competitive destination containing:

- Arcade Skirmishes: The original arcade combat experiences and their established engine builds.
- 5v5 Competitive Combat: USSF versus Accord multiplayer battles.
- Live Competitions: Actual active matches visible to approaching players.
- Spectator Access: Players can observe a competition before deciding to enter.
- Match Entry: Eligible players can join available matches or queue for the next competition.

## What I believe the development plan should mean

| Component                  | Intended responsibility                              |
| -------------------------- | ---------------------------------------------------- |
| Orbital Combat Lab         | Develop, test, and validate combat simulation        |
| Original flight simulation | Remain an independent playable experience            |
| Arcade Skirmishes          | Preserve and integrate the established arcade modes  |
| Asteroid destination       | Host and expose competitive experiences              |
| 5v5 Wing                   | Deliver the competitive multiplayer battles          |
| Universe layer             | Connect destinations, players, and active operations |

One qualification: I can confirm that this is the architectural direction we should implement, but I cannot claim that the existing asteroid implementation already provides these capabilities. The recent Orbital Combat Lab integration established an offline simulation foundation and server-side test harness, not a complete live 5v5 asteroid competition system.

## One important point I want to settle

I would not make the asteroid exclusively a 5v5 arena. It should be a competitive operations hub that can host multiple kinds of combat experiences simultaneously.

For example:

- Asteroid Arena A: 5v5 USSF versus Accord.
- Asteroid Arena B: Arcade Skirmish.
- Asteroid Arena C: Competitive free-for-all.
- Asteroid Arena D: Cooperative combat operation.

Players can see these competitions happening in the same universe without requiring every battle to run inside one giant shared simulation.

My recommendation: Preserve the original combat engines, use the asteroid as their shared physical competitive destination, and use the Three.js universe to let players discover, approach, observe, and enter those competitions.

That gives War for Mars the connected multiplayer universe you have been describing without sacrificing the gameplay and engine development already invested in.
