# WAR FOR MARS: THE INFINITE WAR — structural rebuild strategy

I agree with your diagnosis. The screenshot exposes a fundamental game-design and architecture problem: WFM is presenting the player with a collection of separate experiences instead of guiding the player through one unified game.

The issue is not that the individual commands are necessarily bad. Many represent useful systems we have developed: campaign, cooperative missions, orbital combat, persistent galaxy, armory, upgrades, 5v5 multiplayer and leaderboards.

The issue is that they currently appear as separate destinations, with different levels of integration and different gameplay rules. The player is being asked to choose between pieces of the game instead of entering a world in which those pieces work together.

I recommend a fundamental change:

The Orbital Combat Lab should become the foundation of the new WFM runtime—not another game mode alongside the old game modes.

We should consolidate the useful systems into one authoritative game structure, one universe, one campaign timeline, one player identity and one progression system. We should not blindly delete the older implementations, though. Some contain valuable server, account, multiplayer and persistence infrastructure that the new combat prototype does not yet replace.

This inventory is grounded in the current project documents. It does not mean every system is complete, deployed or connected to every other system.

For example, the repository documents the cooperative mission chain and Iron Eclipse separately from the 5v5 Wing system. That separation is exactly the kind of fragmentation we need to address.

### The most important architectural finding

The repository already has several valuable pieces of the intended foundation:

- A custom Three.js renderer.
- A deterministic 3D flight simulation.
- A shared orbital simulation package.
- Server-owned cooperative mission state.
- Authenticated player identity and account-scoped progression.
- Competitive matchmaking and reward protections.
- A campaign, economy and world-services foundation.

The correct direction is one game architecture with multiple connected subsystems, not several independent game engines.

One clarification: PR #11 continues the custom Three.js/Vite runtime. It adds a Needle Engine research skill, but it does not migrate the game to Needle. We should not accidentally turn this consolidation project into another engine migration.

Player journey

1. Open Infinite War and see the cinematic introduction.
2. Choose USSF or Accord.
3. Enter the 3D hangar and select a fighter.
4. Open the universe map and select Rust Disc.
5. Launch into the new orbital combat runtime.
6. Fight a hostile force using flight, targeting, missiles and damage.
7. Complete a mission objective and extract.
8. Return to the hangar and see validated account progression.
9. Unlock the next story operation: Mars Approach.

First milestone acceptance

- One unified application and navigation.
- One canonical flight/combat simulation.
- At least one playable story operation.
- One complete mission-to-debrief-to-progression loop.
- No duplicate or misleading command destinations.
- Existing multiplayer and account systems preserved.

After this works, we connect Iron Eclipse, squad orders and the existing 5v5 system. Then we make the warfronts part of the universe.

## 5. My recommendation on what to do with the current code

I would use the following policy:

| Decision                            | Treatment                                                                                                                                      |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Orbital Combat Lab                  | Evolve into the canonical combat foundation                                                                                                    |
| Rust Disc                           | Retain its 3D flight, training and sector capabilities; consolidate overlapping simulation code                                                |
| Iron Eclipse                        | Retain and integrate as a major cooperative operation                                                                                          |
| 5v5 Wing                            | Retain its server-authoritative matchmaking, rewards and multiplayer contracts; integrate its gameplay into the new combat model incrementally |
| Campaign                            | Retain story and progression; connect it to the new mission framework                                                                          |
| Armory / Market                     | Retain, consolidate and connect to the unified hangar                                                                                          |
| Persistent Galaxy                   | Evolve into the actual universe-navigation system                                                                                              |
| Old menu commands                   | Replace with contextual navigation and connected destinations                                                                                  |
| Duplicate frameworks or simulations | Retire only after proven replacements                                                                                                          |
| Needle Engine                       | Keep as a research/authoring candidate, not a second production runtime                                                                        |

One particularly important decision: don't discard the existing planar Wing system or its reward logic just because the orbital combat prototype is newer. The existing 5v5 system contains valuable authentication, matchmaking, account and reward safeguards. We need to migrate its combat behavior into the new simulation without losing those guarantees.

3. What it is replacing and why.
4. What it has actually connected.
5. Which gameplay flows now work end to end.
6. Which tests passed and which failed.
7. What remains isolated or incomplete.
8. The exact commit and pull request containing the work.
